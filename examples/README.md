# Example outputs

Three full output sets from the skill, drawn from the canonical test scenarios. Each shows the complete set of artifacts the skill produces for one type of invocation.

## `from-scratch-internal-tool/`

**Scenario:** From scratch (empty data sources — no PRD, brief, backlog, or tracker) — A fintech engineer has a verbal-only ask from CS leadership: build a self-service refund portal so customer success can refund individual transactions without filing engineering tickets. 4 engineers + 1 PM, 12-week PI starting in 3 weeks, PI planning next Thursday. WSJF + SAFe PI.

**What the skill produced:**
- `design.md` — outcome, personas (CS Agent / CS Lead / Engineer / Finance), 6-activity backbone in user voice, hypotheses, non-goals, decisions log
- `storymap.md` — 47 stories across 6 activities × 12 tasks, sliced PI 1 / PI 2 / PI 3
- `storymap.csv` + `storymap.mmd` — derived via bundled scripts
- `backlog.csv` — full WSJF table with per-row reasoning
- `backlog.md` — top-10 ranked + per-slice tables + PI 1 backbone-coverage check
- `handoff.md` — what's uncertain + smallest next decision before PI planning

**Demonstrates:** the basic from-scratch workflow, WSJF scoring, SAFe PI slicing, backbone in user voice (Sign in & find → Review → Initiate → Approve → Execute → Audit), and the "smallest next decision" handoff pattern.

## `multi-stakeholder-conflict/`

**Scenario:** Scoping an internal developer platform with two stakeholder groups that have conflicting interests — Platform team wants tight governance (approval workflows, mandatory tags, cost limits), Application developers want speed (minimum friction, no approval gates non-prod). The user (VP Engineering) explicitly states: "I lean strongly toward developer velocity. Do NOT recommend approval-gated env creation in PI 1 — that's a non-starter for me politically, even if simulation tells you the platform team wants it."

**What the skill produced:**
- All six no-tracker files (no issue tracker here) — `design.md`, `storymap.{md,csv,mmd}`, `backlog.{md,csv}` — + `slice-1-acceptance-criteria.md` + `handoff.md`
- `design.md` includes a persona conflict matrix with explicit resolution per row
- `decisions log` records "Approval-gated env creation: deferred per VP Eng stance, despite platform-team simulation arguing for it" citing the user-input-authoritative principle
- Platform-team objections are NOT silenced — they appear as deferred risks for PI 2 / PI 3 (compensating controls in PI 1)

**Demonstrates:** the user-input-authoritative principle in action. The simulated platform-team persona argued for approval gates; the user's prior stance won every conflict; the platform-team voice is preserved as sequenced compensating work rather than dismissed.

## `snapshot-and-breaks-limits/`

**Scenario:** Refinement of an existing map (the loop re-run on a non-empty baseline) — 6 weeks into a 12-week PI, sales sold a $400K ARR deal that requires SCIM provisioning before EOQ. The user wants a snapshot of where PI 1 stands + an analysis of whether the new feature fits + what trade-offs are required.

**What the skill produced:**
- **A tracker is the system of record here**, so the local data files (`storymap.csv`, `storymap.mmd`, `backlog.md`, `backlog.csv`) are **not** produced — only the always-files `design.md` + `storymap.md`, plus a `tracker-status-update.sh` that writes the new stories + burn-down fields (points/sprint/status) back to the tracker. PLUS:
- `breach-decisions.md` — the required breach-decision document
- `handoff.md` with a Step D.5 refinement diff at top showing what changed

**Six breaches detected and surfaced:**
1. **Capacity** — PI 1 was already ~20 SP underwater BEFORE SCIM was even on the table; with F-SCIM, ~38-46 SP over. Five trade-off options A-E.
2. **New backbone activity** — "Provision tenant users" added; slice-1 coverage required. Three options.
3. **SOC 2 vs SCIM deadlines collide** — both racing for the final 5 weeks; specific stories locked vs deferable.
4. **F-SCIM decomposition** — proposed 4 stories totalling 26 SP with sizes.
5. **Decisions-log check** — verified F-SCIM does NOT conflict with "No AI auto-approve on refunds" (different feature area).
6. **KR-2.1 displacement** — default cuts S006+S007 (over-$100 refund flow), requiring re-baseline with stakeholder.

**Demonstrates:** the refinement protocol (the loop on a non-empty baseline) — snapshot, breach detection, trade-off generation, diff-style handoff. Critically: nothing was silently absorbed. The agent surfaced one breach (the pre-existing PI 1 overcommit) that wasn't even in the user's prompt. Also demonstrates the v0.0.4 **tracker-conditional output**: with a tracker as the system of record, the local data files (`storymap.csv`/`.mmd`, `backlog.{md,csv}`) are not produced — the plan + burn-down go into the tracker via the opt-in write-back.
